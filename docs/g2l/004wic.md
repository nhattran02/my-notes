# Flashing a full SD card image

The fastest way to get a bootable SD card: write the `.wic` image produced by Yocto. It already contains the partition table, kernel, device tree and root filesystem. Compared to [building the partitions by hand](003sd_emmc.md), there is nothing to partition or copy.

## Variables

```bash
export DEPLOY=~/yocto/rzg2l_vlp_v3.0.x/build/tmp/deploy/images/smarc-rzg2l
export WIC=$DEPLOY/core-image-minimal-smarc-rzg2l.wic.gz
export SDCARD=/dev/sdX          # set after checking lsblk
```

## Find the SD card device

```bash
lsblk -d -o NAME,SIZE,MODEL,TRAN
```

Insert the card, run it again, and take the new entry (`sdb`, `sdc`, or `mmcblk0` for a built-in reader).

!!! danger
    Writing to the wrong device destroys its data (possibly the host's own disk). The SD card is the device that appears only after inserting the card, with the card's size.

## Write the image

=== "Linux: bmaptool (fast)"

    Writes only the used blocks, using the `.wic.bmap` file next to the image:

    ```bash
    sudo umount ${SDCARD}* 2>/dev/null
    sudo bmaptool copy $WIC $SDCARD
    ```

=== "Linux: dd"

    ```bash
    sudo umount ${SDCARD}* 2>/dev/null
    gunzip -c $WIC | sudo dd of=$SDCARD bs=4M conv=fsync status=progress
    ```

    For `.wic.xz` use `xz -dc`, for `.wic.bz2` use `bzip2 -dc`.

=== "Windows"

    1. Decompress the `.wic.gz` (7-Zip) to get the `.wic` file.
    2. Write it with [balenaEtcher](https://etcher.balena.io/){: target=_blank } or Win32 Disk Imager (rename to `.img` if the tool does not list `.wic`).
    3. Ignore the Windows message asking to format the disk. Click *Cancel*.

## Check the partitions

```bash
sudo fdisk -l $SDCARD
lsblk $SDCARD
```

Mount and look at the content, to know where the kernel and dtb are:

```bash
sudo mount ${SDCARD}1 /mnt && ls /mnt && sudo umount /mnt
sudo mount ${SDCARD}2 /mnt && ls /mnt /mnt/boot && sudo umount /mnt
```

## Boot from the card

Insert the card into the board and stop at the U-Boot prompt. Check where the files are from U-Boot as well:

```
mmc dev 1
mmc part
ls mmc 1:1
ls mmc 1:2 /boot
```

If the BSP's default environment already boots from SD, `boot` is enough. Otherwise set `bootcmd` according to where `Image` was found:

=== "Kernel on partition 1"

    ```
    setenv bootargs 'console=ttySC0,115200n8 rootwait root=/dev/mmcblk1p2 rw'
    setenv bootcmd 'mmc dev 1; load mmc 1:1 0x48080000 Image; load mmc 1:1 0x48000000 r9a07g044l2-smarc.dtb; booti 0x48080000 - 0x48000000'
    saveenv
    boot
    ```

=== "Kernel in /boot of partition 2"

    ```
    setenv bootargs 'console=ttySC0,115200n8 rootwait root=/dev/mmcblk1p2 rw'
    setenv bootcmd 'mmc dev 1; load mmc 1:2 0x48080000 /boot/Image; load mmc 1:2 0x48000000 /boot/r9a07g044l2-smarc.dtb; booti 0x48080000 - 0x48000000'
    saveenv
    boot
    ```

## Grow the rootfs to the full card

The `.wic` rootfs partition is only as big as the image. Extend it to use the whole card, on the host with the card inserted (not mounted):

```bash
sudo parted $SDCARD resizepart 2 100%
sudo e2fsck -f ${SDCARD}2
sudo resize2fs ${SDCARD}2
```

!!! note
    For a built-in reader the partitions are named `${SDCARD}p1`, `${SDCARD}p2` (for example `/dev/mmcblk0p2`).

## Write the same image to eMMC

The eMMC is only reachable from the board. Boot Linux from SD or NFS, copy the `.wic.gz` and `.wic.bmap` to the board, then:

```bash
bmaptool copy core-image-minimal-smarc-rzg2l.wic.gz /dev/mmcblk0
```

Or without `bmaptool`:

```bash
gunzip -c core-image-minimal-smarc-rzg2l.wic.gz | dd of=/dev/mmcblk0 bs=4M conv=fsync
```

Then use `mmc 0` and `root=/dev/mmcblk0p2` in the U-Boot commands above.

!!! warning
    Do not write to `/dev/mmcblk0` while the board's root filesystem is on it. Boot from SD or NFS first.

## Troubleshooting

| Symptom | Cause / fix |
| ------- | ----------- |
| `bmaptool: ERROR: cannot open bmap file` | `.wic.bmap` missing next to the image. Use `bmaptool copy --nobmap` or `dd` |
| `dd: failed to open '/dev/sdX': Permission denied` | Run with `sudo`, and check `SDCARD` is set to the real device |
| Board does not find the card in U-Boot | Card not fully inserted, or SW settings select eMMC for SDHI0. `mmc rescan`, `mmc list` |
| Kernel boots but `Waiting for root device /dev/mmcblk1p2...` forever | Wrong `root=` (SD vs. eMMC number), or the card's rootfs partition has a different number. Check `mmc part` |
| `resize2fs: Bad magic number in super-block` | Wrong partition. Check with `lsblk -f` which partition is ext4 |
